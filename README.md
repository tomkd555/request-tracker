# Request Tracker

**Request Tracker** は、小規模チーム向けの Windows デスクトップ用タスク・課題管理アプリケーションです。  
共有ネットワークドライブや同期フォルダー上の単一フォルダー内に JSON ファイルとしてデータを保存・同期するため、専用のデータベースサーバーを構築する必要がありません。

---

## 主な機能

- **階層構造**: 親課題と子課題のツリー管理（最大5階層）
- **柔軟な属性設定**: 状態・優先度・種別・ラベル・担当者の個別設定
- **進捗・時間管理**: 開始日・期限・マイルストーン設定、予定時間と実績時間の記録
- **課題間のリンク**: 課題同士の関連付けおよび関連種別の指定
- **カスタム項目（汎用列）**: プロジェクトごとに独自の入力項目を追加（自由入力 / 選択肢形式）
- **ツリー型課題一覧**: 折りたたみ対応、条件指定絞り込み（ビュー保存可）、一括編集、CSV インポート/エクスポート
- **カンバン & ガントチャート**: ドラッグ＆ドロップによるステータス更新・期間変更
- **バーンダウンチャート**: マイルストーン進捗の可視化および `.ics` 形式（カレンダー）エクスポート
- **変更通知**: 自身が登録・担当・ウォッチしている未完了課題の更新通知
- **アクティビティログ**: プロジェクト全体の最近の更新履歴一覧
- **コメント & 添付ファイル**: 課題や Wiki ページの変更履歴管理（過去バージョンへの復元対応）
- **Markdown Wiki**: ツリー状に整理可能な Wiki 機能（`[[タイトル]]` リンク、差分（diff）表示対応）
- **横断検索**: 課題・コメント・Wiki の一括テキスト検索
- **集計・分析**: 月別の課題数・予定時間・実績時間の自動集計
- **レポート作成**: チーム外部向けのレポート作成、HTML / Markdown 形式でのエクスポート
- **プロジェクト設定**: 種別・状態・ラベル・マイルストーン・メンバー・テンプレートの個別設定およびエクスポート/インポート

## 動作環境

- **対応 OS**: Windows 10 以降（64 ビット版）
- **前提条件**: 利用者全員が書き込み権限を持つ共有フォルダー（共有ネットワークドライブ推奨）

---

## 導入手順

1. **ダウンロード**  
   [Releases](https://github.com/tomkd555/request-tracker/releases) から最新の `RequestTracker-<version>.exe` をダウンロードします（インストール不要のポータブル版です。※コード署名なし）。
2. **共有フォルダーの指定**  
   ダウンロードした `.exe` を実行し、データ保存用の共有フォルダーを選択します（既存プロジェクトがない場合は自動生成されます）。
3. **利用開始**  
   自身のユーザー名を入力するか、既存メンバー一覧から選択すると課題一覧画面が開きます。

## データ管理の仕組み

本アプリは共有フォルダーを簡易データベースとして使用します。課題、コメント、Wiki ページ、レポートは 1 件につき 1 つの JSON ファイルとして保存され、添付ファイルは同一ディレクトリ内に格納されます。

- **安全な書き込み処理**: データをまず一時ファイルに書き込んだ後に本来のファイル名へリネーム（アトミックな置換）を行うため、書き込み中のアプリ強制終了等によるファイル破損を防ぎます。
- **履歴管理とごみ箱**: 課題、Wiki、`project.json` の更新前データは `history/` フォルダーに自動保存されます。削除されたデータは `trash/` フォルダーへ移動します。
- **楽観的排他制御**: 編集中のデータが他のユーザーによって更新された場合、上書き保存を防止して再読み込みを促す通知を表示します。
- **重複のないキー発行**: 課題キーは `YY-NNNN` 形式（年度-連番）で管理されます。新規作成時にファイル存在チェックを行うことで、複数端末での同時作成時でもキーの重複を防ぎます。
- **ウォッチリスト**: ユーザーごとのウォッチ課題キーは `watch/<メンバー ID>.json` に保存されます。
- **同期タイミング**: 画面開閉時、保存完了時、および［更新］ボタン押下時にフォルダーを読み込みます（常時バックグラウンド監視は行いません）。

### 同期フォルダー（OneDrive 等）利用時の注意点
共有ネットワークドライブでは全端末がリアルタイムに同一ファイルを操作するため重複防止機構が完全機能しますが、**OneDrive 等の同期フォルダーでは同期遅延によるキー重複や競合コピーが発生する可能性があります**。複数人で同時編集を行う運用では、**共有ネットワークドライブの利用を強く推奨します**。

### 技術スタック

- **Framework / Library**: Electron, electron-vite, React, TypeScript

### ソースコード構造

```text
src/
├── main/
│   ├── store/      # ファイルシステムアクセス（コレクション管理・ユーザー識別・設定）
│   └── ipc.ts      # IPC ハンドラー（Renderer からメインプロセスへの唯一のエントリポイント）
├── preload/
│   └── index.ts    # contextBridge を用いた window.api の公開（型定義: src/shared/api.ts）
├── shared/
│   └── types.ts    # データ構造・スキーマ定義（レコード型）
└── renderer/       # React UI（アプリケーション枠、課題管理、カンバン、ガントチャート、Wiki、検索、レポート）
```
