# Request Tracker

Request Tracker は、小規模なチームが依頼を登録し、対応状況を管理するための Windows 用デスクトップアプリです。チーム全員のアプリが、共有ネットワークドライブまたは同期フォルダーに配置した1つのフォルダーで JSON ファイルを読み書きするため、サーバーを用意する必要はありません。

アプリの画面は日本語で、1件の依頼を「課題」と呼びます。

## 主な機能

- 親課題と子課題（5階層まで）
- 課題ごとに設定できる状態、優先度、種別、ラベル、担当者
- 課題ごとの開始日と期限、マイルストーン、予定時間と実績時間
- 課題どうしの関連付けと、関連の種類の指定
- 課題に独自の項目を追加する汎用列。プロジェクトごとに追加でき、値は自由入力または選択肢から選ぶ形式です
- 折りたためるツリー形式の課題一覧。絞り込み、絞り込み条件の保存、一括編集、CSV のエクスポートとインポートに対応しています
- カンバンとガントチャート。カードとバーはドラッグ＆ドロップで動かせます
- マイルストーンのバーンダウンチャート。マイルストーンの期限は .ics 形式でエクスポートできます
- ほかのメンバーによる変更の通知。自分が登録した課題、担当している課題、ウォッチしている課題のうち、未完了の課題が対象です
- プロジェクト全体の最近の更新の一覧
- コメント、ファイルとフォルダーの添付。課題と Wiki ページの以前の版は、変更履歴から復元できます
- ツリー状に整理できる Markdown の Wiki。`[[タイトル]]` 形式のリンクと、版どうしの差分表示に対応しています
- 課題、コメント、Wiki の横断検索
- 課題数、予定時間、実績時間の月ごとの集計
- チーム外の相手に渡すレポートの作成と、HTML または Markdown 形式でのエクスポート
- プロジェクトごとの種別、状態、ラベル、マイルストーン、メンバー、テンプレートの設定
- これらのプロジェクト設定のエクスポートとインポート

## 導入手順

1. [Releases](https://github.com/tomkd555/request-tracker/releases) から `RequestTracker-<version>.exe` をダウンロードします。この exe はインストール不要のポータブル版で、コード署名はありません。
2. exe を実行し、共有フォルダーを選びます。フォルダーにプロジェクトがない場合は、アプリが新しいプロジェクトを作成します。
3. 自分の名前を入力するか、登録済みのメンバーの一覧から選ぶと、課題一覧が開きます。

動作環境は、64 ビット版の Windows 10 以降です。また、利用者全員が書き込める共有フォルダーを用意してください。

## 仕組み

アプリは、共有フォルダーをデータベースとして使います。課題、コメント、Wiki ページ、レポートを1件ごとに1つの JSON ファイルとして保存し、添付ファイルをその隣にコピーします。

- アプリは、レコードをまず一時ファイルに書き込み、その一時ファイルの名前を本来のファイル名に変更します。そのため、書き込みの途中でアプリが止まっても、元のファイルはそのまま残ります。
- 課題、Wiki ページ、レポート、`project.json` を上書きする前に、アプリは以前の版を `history/` にコピーします。レコードを削除すると、ファイルは `trash/` に移動します。
- 課題、Wiki ページ、レポートを開いたあとにほかのメンバーが変更した場合は保存できず、再読み込みを求めるメッセージが表示されます。
- 課題のキーは `YY-NNNN` の形式です。`YY` は年度、`NNNN` は連番を表します。アプリは、同じ名前のファイルがまだない場合に限ってキーごとのファイルを作成し、そのキーを確保します。そのため、2台の PC で同時に課題を作成しても、別々のキーが割り当てられます。
- キーの重複と上書きを防ぐこれらの仕組みは、共有ネットワークドライブで有効です。共有ネットワークドライブでは、すべてのアプリが同じファイルを操作するからです。
- OneDrive などの同期フォルダーでは、同期クライアントが変更をほかの PC にコピーし終えるまで、各 PC のアプリはその PC 上のコピーを読み書きします。この間に2台の PC で課題を作成すると、同じキーが割り当てられます。同じ課題を2台で保存した場合も、どちらの保存も成功します。同期クライアントは2つのファイルのうち1つを別名の競合コピーとして残しますが、アプリは競合コピーを一覧に表示しません。そのため、複数の人が同時に編集するチームでは、共有ネットワークドライブを使ってください。
- 各メンバーがウォッチしている課題のキーは、`watch/<メンバー ID>.json` に保存されます。
- アプリが共有フォルダーを読み込むのは、画面を開いたとき、保存したあと、［更新］ボタンを押したときです。それ以外のタイミングでは、フォルダーの変更を監視しません。

## 開発

```
npm install
npm run dev          # ホットリロード付きで1つ起動する
npm run dev:second   # 別のユーザーデータで2つ目を起動する（2台での動作確認用）
npm run typecheck    # main/preload と renderer の型チェック
npm run package      # ビルドして dist/RequestTracker-<version>.exe を作成する
```

使用技術: Electron、electron-vite、React、TypeScript

ソースの構成:

```
src/main/store/          ファイルシステムへのすべてのアクセス（コレクション、利用者の識別、設定）
src/main/ipc.ts          IPC ハンドラー。renderer からファイルシステムに届く唯一の経路
src/preload/index.ts     window.api を公開する contextBridge（型は src/shared/api.ts）
src/shared/types.ts      レコードの型。このファイルがスキーマ
src/renderer/            React の画面（アプリの枠、課題、カンバン、検索、Wiki、ガントチャート、レポート）
```

## セキュリティ

- レンダラープロセスは、`sandbox` と `contextIsolation` を有効にし、`nodeIntegration` を無効にして動作します。ファイルシステムには、型付きの IPC ハンドラーを通してだけアクセスします。
- Markdown は、生の HTML を無効にして表示します。
- アプリはパスワードとトークンを保存しません。

脆弱性は、リポジトリの Security タブにある「Report a vulnerability」から報告してください。
